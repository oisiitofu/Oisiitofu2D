# スマホのオンライン設定・画像準備

2026-11-02。オンライン設定の表示は `body.touch-mode` に限定して整理した。名前候補を幅に応じた2〜3列へ並べ、自由入力・保存を維持。作成時はルールに集中し、参加後は部屋情報と準備完了を先に見せる。名前設定は同じ画面の下部から変更可能。横持ちは名前設定と部屋情報を2列にする。ルール編集もスマホだけ2列にし、文字入力/選択は16pxを維持する。

遅延原因：ArtLoader.initが全キャラの一覧画像のdecodeを待ち、ステージの小さなプレビューにもフルサイズ背景を一斉に読み込んでいた。さらに起動時は対戦に選ばれていない既定ステージの画像まで準備してからloadedになっていた。

スマホのみ、manifestと寸法情報の初期化後に操作可能とし、一覧はlazy/低優先度へ変更。ステージのプレビューは表示範囲に入った画像だけIntersectionObserverで読み込む。元の画像・解像度は変更しない。実際の対戦では選択キャラ（変身・団体戦の形態を含む）の画像・カラー・エフェクト、確定したステージを全て準備する。キャラ準備は最大2件並列とし、必要な画像は高優先度で読み込む。旧2ステージの背景/足場も開始前に準備する。PCの初期ロード順・一覧表示は維持。

サーバーのprepare → 各端末のloaded → startの待ち合わせ、キャラ選択の秘匿、同じ入力による同期は変更しない。未使用画像を開始条件から外し、必要な画像の条件は緩めない。

検証：同じ未圧縮バンドル配信、40ms遅延・2MB/sダウンロード・CPU2倍スロットリングの比較で、初期準備21.1秒/40.6MB/268リクエスト → 2.6秒/7.0MB/40リクエスト。実際の配信バンドルは従来どおりgzip等で圧縮される。値はこの検証環境の測定で、実機・回線ごとの短縮時間を保証するものではない。
