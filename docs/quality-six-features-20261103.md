# キャラ選択・結果・見やすさの6項目

## 作品と使用履歴

カードと名前リストに登場作品の選択を追加。`CharacterOrigins` / `Roster.definitions.origin`を使い、テイルズ各作品は「テイルズシリーズ」にまとめる。FFは「FF / ファイナルファンタジー」と表示。名前リストの検索は作品名とFFの略称も対象。通常の選択順・通し番号・非表示形態・おまかせの扱いは維持する。

「すべて」「お気に入り」「最近使った」を作品と組み合わせて選べる。お気に入りはカードと名前リストで共有。最近使ったキャラは実際の対戦開始時に記録し、CPUとオンラインの他の席を除く。団体戦は自分の編成を記録する。重複なし12体まで、最近の順で両画面へ出せる。両方ともブラウザ保存し、保存できない場合はページ内のメモリーで保持する。履歴・好みはオンラインへ送信しない。

## 結果と再戦

`BattleReport`は実際に通過した命中、シミュレーションのフレームと場外状態、KOを観測する。撃墜につながった技、復帰失敗、よく当たった上位3技を各プレイヤーに表示する。シールド・パリィ・無敵・つかみ開始は命中へ含めず、多段は各接触を数える。つかみ攻撃も命中へ含める。召喚・独立弾は`sourceType`の元の技名を優先する。技名を確定できない撃墜は「技を特定できません」と表示する。

復帰失敗の定義：足場の外や下を空中で通過し、着地・崖つかまりする前に主足場より120px以上下でKOになり、その時に被弾硬直・吹っ飛び予約がなく、直近45Fの吹っ飛び命中もない落下。直撃で下へ飛ばされたKOと区別する集計上の定義であり、プレイヤーの意図や判断ミスを推定しない。定義と多段の数え方は結果画面にも記載した。集計は戦闘や勝敗、吹っ飛び、入力へ影響しない。

ローカルの「同じ条件で再戦」は、開始時に確定したキャラ・カラー・ステージ・ストック・時間・チーム・編成・1対1補正を使う。おまかせを再抽選しない。オンラインは従来の全員の終了確認・ready・画像準備の待ち合わせを維持する。「キャラを変更」「ルームへ戻る」は同じ部屋を維持。ビンゴの次ラウンド/カード配布、秘匿、サーバーによる変更拒否を維持する。データをスクロールしても操作ボタンを下部へ残す。

## 勝利画面

縦長の枠を覆う拡大をやめ、縦横比を保って収める。小さい元画像は論理座標で1.1倍までにし、頭・肩と余白を確認した。レイ、ディートリヒ、ナルメア、マロ、ハイデリン、ベルベットの実描画を比較。横長画面の余白へはみ出した戦闘HUDも覆う。

さらにディートリヒ、ナルメア、イオ、ベルベット、ナミネ、ハイデリン、魔王、オディオは、カード用の切り詰めた画像とは別に、承認済み高解像度原画の全域を5カラーで配信用に焼いた。元の顔・衣装・配色を保持し、カードの寄りは変更しない。`ART_PRESENTATION_ONLY=1 ART_IDS=... node .tools/build-art.cjs`で再生成可能。通常の再生成でも専用ソースの`presentation`フラグを維持する。

勝利用画像は選ばれたキャラ/カラーだけ試合の準備中に読み込み、未使用のキャラの画像は先読みしない。読み込み完了まで従来のready条件を通さない。不要になった専用画像のキャッシュは解放する。カードを数体へ絞った時は、既存のネイティブ画像もsrcsetの候補にし、560pxサムネイルだけの拡大を避ける。

## 見やすさ

詳細設定に文字100/120/140%、画面揺れ（標準/弱め/なし）、画面全体の明滅と共通無敵点滅（標準/弱め/なし）、マーカー（標準/大きい/非表示）、記号/番号/状態名を追加。ブラウザ保存する。文字拡大時はカードも大きくしてスクロール可能にし、表示件数に合わせるために文字を再縮小しない。頭上とHUDへ席ごとの●■▲◆と番号を使い、無敵・被弾・しりもち・ガードも文字で区別できる。無敵時間や技の判定を変えずに点滅を抑える。OSの動き軽減設定がある場合、初期値の揺れ/明滅をなしにする。

[Game Accessibility Guidelinesの基本項目](https://gameaccessibilityguidelines.com/basic/)の読みやすい文字・色だけへ依存しない表示と、[明滅の項目](https://gameaccessibilityguidelines.com/avoid-flickering-images-and-repetitive-patterns/)を参照した。これは各種ガイドライン全体への適合認定を示すものではない。

## 検証

- `quality-features-test.cjs`：作品・お気に入り連携、実際の命中/撃墜技/復帰落下、同条件再戦、CPUを除く履歴と保存、表示設定の保存、表示設定を変えても同じ25フレームの物理状態、勝利6キャラの実描画。
- `quality-layout-test.cjs`：320×568/390×844/844×390/1280×720/1920×1080の文字100%/140%、4人の結果、操作ボタンの到達、実描画の番号/状態名、揺れなし/明滅なし、無敵状態が変わらないこと。
- `presentation-portraits-test.cjs`：8体×5カラーで原画解像度とカード範囲の可視RGB/alphaが一致。完全透明画素の不可視RGBは正規化して比較。
- `art-loading-test.cjs`：対象9体の730ポーズ・120エフェクト・3650カラーで既存チェックサムと一致。
- `fighter-list-test.cjs`：名前/読み検索、あいうえお順、番号、CPU選択、保存拒否時の保持など18項目。固定の旧キャラ数を現在の選択可能件数へ改めた。
- `result-readiness-online-test.cjs`：4クライアント、同じ部屋での再戦、3人団体戦、退出/再参加、ビンゴの次ラウンドと秘匿、「ルームへ戻る」での同じ部屋の維持、再戦60フレーム一致など55項目。増えたデータはスクロール可能なので、以前の「全情報をスクロールなしで表示」の検証を画面内への収まりと操作到達へ改めた。
- `result-readiness-ui-test.cjs`：13項目。使用履歴は新たに保存するため、再戦後のストレージ全体不変という旧条件を、お気に入りを保持する条件へ変更。
- `mobile-controls-test.cjs`：3指同時入力、長押し/取りこぼし/方向、縦横の操作を維持。
- `mobile-controls-online-test.cjs`：スマホとPCの110フレーム一致。

iPhone実機での操作はこの環境では未確認。表示設定と追加UIはブラウザのPC/スマホ環境で確認した。

勝利画像の横位置は、カードのために調整済みの顔の中心を元原画の座標へ戻して合わせる。生成済み配信画像は従来どおりGit管理外のassets/ready/に置き、GitHubには元画像を参照する定義と再生成処理を反映する。
