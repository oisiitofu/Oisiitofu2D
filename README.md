# おいしいとうふブラザーズ

GitHubへの保存・別のPCでの起動手順は[GIT-WORKFLOW.md](GIT-WORKFLOW.md)を参照してください。

## キャラ別のフォルダ

キャラ専用ファイルは `characters/<キャラID>/` にまとめています。[キャラ一覧と配置ルール](characters/README.md)から各フォルダを開けます。技・固有ルールは `<ID>-data.js`、描画は `<ID>-art.js` と `<ID>-vfx.js`、元画像は `assets/`、専用テストとその設定は `tests/`、実装メモは `docs/` です。検証画像の `previews/` はGit管理外です。

コマンドはプロジェクトのルートから実行します。例：`node characters/midna/tests/midna-warp-test.cjs`。共通テストは従来通りルート、`npm test` は新しい配置に対応しています。共通エンジン、ステージ素材、音声、配信用キャッシュ `assets/ready/` は共有します。

## キャラの表示サイズ

`battle-size.js`の`calibration`で全113形態の表示を調整します。`height`は透明な余白を除いた体の高さ、`body`は元画像上の基準寸法、`neutral`は待機ポーズだけの補正、`pads`は各ポーズの足元の透明な余白です。小柄なキャラ・人型・大型の体格差を残し、しゃがみや前傾を立ち姿と同じ高さへ引き伸ばしません。接地中の全身上下揺れを抑え、崖つかまりでは足元補正を使わず手の位置を基準にします。戦闘の判定寸法は表示用のサイズから独立しています。検証は`node battle-size-test.cjs`。

## 2〜4人対戦・チーム戦・ストック数

キャラ選択画面の「対戦設定」で人数（2・3・4人）、個人戦／チーム戦、ストック数（1〜10）を選択します。ローカルは各参加者にCPU・キーボード・パッド1〜4を割り当て、参加者タブからキャラとカラーを選びます。ストック数はブラウザに保存されます。団体戦は従来通り3人／5人を各1ストックで交代します。

チーム戦は赤・青に分かれ、チームアタックは常に有効。脱落した参加者は「通常攻撃＋必殺技」で、残り2ストック以上ある味方から1ストックを受け取って復帰できます。味方の最後の1ストックは取れません。CPUは条件を満たすと自動で受け取ります。

2人目用キーボードはI/J/K/Lで移動、N/Bでジャンプ、Uで攻撃、Oで必殺、Hでつかみ、Yでガード、Tで強攻撃、Gでスマッシュ。通常のキー設定は詳細設定から変更できます。パッドは接続順で1〜4となります。

オンラインルームは最大4人。ルーム作成前に人数・形式を設定し、参加者全員が準備完了すると開始します。ストック数と1対1補正は作成者の設定、チームは各参加者の設定を使用。ステージは参加者の希望から等確率で抽選します。

実装は `multiplayer.js`。参加者IDは0〜3、チームIDとは独立しています。キャラ固有の狙いは `BattlePlayers.target(f)`、攻撃の接触候補は `BattlePlayers.targets(f)` を使い、`fighters[1-f.id]` のような2人限定の参照は追加しません。検証は `node multiplayer-test.cjs` / `node multiplayer-online-test.cjs`（既定の検証サーバーは4173。`TEST_URL`で指定可能）。

## ステージ選択

キャラ選択画面上部のステージ一覧から選択。矢印・横スクロール・スワイプで移動でき、対戦設定の選択欄とも連動します。「おまかせ」は対戦開始ごとに全ステージから抽選し、選択は再戦後も保持します。

オンラインは参加者の希望から等確率で抽選し、採用された希望が「おまかせ」なら全ステージから抽選。サーバーが決定した同じ足場・ステージ名・BGMを全員で使用します。1対1補正は1Pの設定です。

ステージの名前・足場・BGMフォルダは `stage-data.js` の `StageCatalog.stages` に定義します。追加したステージは一覧・おまかせ・オンラインの抽選候補へ反映され、一覧は一列のまま横にスクロールします。検証: `node stage-selection-test.cjs`。

## フレーム設計（60Hz）

発生・持続・着地隙は提示値を基準とし、後隙は追加の操作感調整に合わせて短縮しています。元の後隙は referenceRecoveryFrames として保存しています。ルキナの公式フレームデータを独立検証したもの、またはスマブラSPの物理の完全再現ではありません。

- 技定義：combat-data.js。startupFrames / activeFrames（複数区間可）/ recoveryFrames / landingLagFrames / totalFrames を全技に持ちます。入力受付が1F、最終判定F＋後隙が全体F、その翌フレームから行動可能。溜め中・ヒットストップ中は技の時間を停止します。
- モーション：予備動作・加速・攻撃・振り抜き・戻りを共通のフレームサンプルから取得。光る武器の線分と攻撃カプセルは同じ座標を使用し、白い刃先は判定のあるフレームだけ表示します。青い斬撃の余韻は判定消滅後7Fで減衰し、追加の攻撃判定は持ちません。既存の40ポーズを位相に応じて変形する構成です。
- 攻撃判定：武器のカプセルと胴体・脚の被判定。前後・上下・斬り下ろしを技ごとに分離。接触は両者の更新後にまとめて計算し、更新順による一方的な勝ちを避けます。
- 硬直：被弾後％、技威力、体重、基本吹っ飛びと成長率から吹っ飛び値を計算。硬直は max(4, floor(吹っ飛び値 × 0.4) − 1)。旧仕様の一律追加硬直は廃止。ヒットストップは威力と技倍率に応じた各キャラ独立の停止で上限30F、終了時にDI・LSIを反映します。トレーニングの表示と実際の戦闘は同じ計算を使用します。
- 先行入力：9F。弱1→弱2、上必殺から空中攻撃はデータのキャンセル区間だけで受け付けます。
- 空中技：空N7F、空上8F、空前・空後10F、空下14Fの着地隙。技の序盤・終盤にはオートキャンセル区間を設け、通常着地3F（急降下5F）へ切り替えます。上必殺は12F目から空中攻撃へ移行可能。空下は急降下し、着地時に左右へ衝撃波を出します。
- スマッシュ：Sまたは弾き＋攻撃で開始。60Fで威力が最大1.4倍になり、最大180Fまで保持できます。Sの入力から技が始まり、押し続けると予備動作で溜めます。離すと続きの発生フレームが進みます。横スマ10～13F、上スマ13～17F、下スマ前6～7F・後21～23F。
- 空後：空中では左右入力で向きを自動反転しません。向きの逆側＋Zで空後。ダッシュ中のZはダッシュ攻撃。
- カウンター：下必殺の6～27Fで受付、成功後4Fで反撃。つかみには無効。

トレーニング画面で敵％を指定し、技フレーム表・判定表示・硬直値を確認できます。frame-test.cjs は全技の各フレーム、着地隙、％成長、メテオ、カウンター、先行入力を検証します。

エフェクトは combat-vfx.js で独立描画。通常斬撃・スマッシュ・突きで異なる帯状の光、分岐雷光、青い残像、命中時の放射光を重ねています。見た目の余韻と当たり判定を分離し、技フレームやダメージ計算は変更しません。

添付 eve.png のデザインを基に、内蔵 imagegen で48ポーズ・専用選択画像・8エフェクトを制作。黒いポニーテール、白と深緑の戦闘服、ブラッドエッジ、ドローンを反映。5カラーは深緑の装甲だけを色替えし、髪・肌・白い服と明度・透過を維持する。

- 通常必殺: ドローンの3連射。X長押しで溜めレーザー。
- 横必殺: その場でショックウェーブ。15～24FにXを押し直すとクロスウェーブと斬撃を追加。相手は弾を避けて接近、または追加攻撃をガードして反撃できる。
- 上必殺: 発動前の左右入力で斜め上への移動方向を選ぶブリンク。到着後にXを押し直すと近距離の相手へ追撃。追撃後・追撃しない場合とも、左右入力で短い離脱方向を選ぶ。床下では外周へ抜けてから真上へ移動し、地形を貫通しない。終了後はしりもち落下。
- 下必殺: タキゲージ100で6秒間変身。攻撃命中でゲージを獲得。通常攻撃の発生・後隙、攻撃力・リーチと移動速度を強化。KOで解除。

技の終了は最後の射撃・追加入力・斬撃に合わせ、待機ポーズで長時間拘束しない。CPUとオンラインにも同じ専用ルールを使用。エフェクトは右向き素材を左右反転してからローカル回転し、実際の剣・弾の方向へ合わせる。
